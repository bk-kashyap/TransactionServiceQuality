# C2: Framework and CI

Implemented seam: tests -> fixtures -> AccountsClient/TransactionApi -> APIRequestContext -> environment config. Clients use relative paths; TEST_ENV and BASE_URL select staging without rewriting calls. Behavioral tests require approved policy or remain blocked.

Fixtures allocate numeric random 14-digit documents and independent account IDs, track created accounts, and remove mock accounts/transactions/replay state in teardown. No DELETE exists in the supplied API: staging attaches generated IDs for an approved retention job. Fixed boundary inputs and captured IDs make failures interpretable without shared account 1 or order dependence.

The reference mock reads supplied schemas plus a separately labeled policy. Prism reads the unchanged YAML and runs @contract checks. scripts/run.cjs starts the local server, refuses occupied ports, waits for readiness and stops its process. Direct Playwright has a webServer fallback. API-only tests need no browsers.

Validation resolves method/template-path/status to YAML response definitions, checks JSON content type and body, and validates typed client requests. Deliberately invalid requests bypass preflight so they reach the endpoint. Error schema and approved policy assertions are separate. Optional properties remain optional; stronger identity/presence expectations are domain oracles.

| Gate | Command | Rationale |
|---|---|---|
| Contract | contract:validate, typecheck, test:prism | Cheap structure/ref/type/contract checks first |
| PR | test:pr | Critical schema/account/amount/operation/integrity and one journey; 20-minute cap within 20-30-minute budget |
| Nightly | npm test in CI; test:nightly locally | Full boundaries, body/HTTP, replay/concurrency and visible blockers |
| Pre-release | test:release | Staging count/journey and required audit/security/state evidence; skipped evidence fails |
| Performance | perf:smoke plus agreed T2 k6 staging run | Local smoke proves harness only; service gates need representative baseline/environment |

Workflow is at repository-root .github/workflows/playwright.yml, running in transaction-service-quality. Contract/functional jobs are separate; reports upload on failure. Staging variables/secrets belong to a protected environment. Release remains blocked on unavailable audit/balance/security observations.

Retries are zero. Investigate first failures as product, environment, test or unknown using traces, case/oracle/risk/environment annotations and response IDs. Preserve original evidence when infrastructure is repaired and rerun. Never retry financial assertion failures into green.

For 100 tests on shared staging: unique account per test/run, keys per logical operation, bounded workers matching capacity, reserved missing IDs and approved retention cleanup. Only deliberate replay cases share a key. The count adapter must return complete consistent state after requests finish. For eventual consistency, agree an observation horizon/completion signal; do not poll until a convenient count appears.
