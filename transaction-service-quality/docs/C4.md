# C4: Executable test design

Tests under accounts, transactions, contract, cross-cutting, idempotency, e2e and gaps record case ID, oracle, C1 risk, defect, gate and environment as Playwright annotations. [TRACEABILITY](TRACEABILITY.md) maps every case to source and observed outcome. Regenerate from a full run using npm run traceability; missing/duplicate metadata fails generation.

@contract cases check supplied schemas/status shapes and harness guards. @behavior cases require the explicit reference policy, locally or in approved staging. @gap cases expose blocked release observations. Execution tags are distinct from oracle authority: a CONTRACT annotation on a wrong property type does not make the assumed exact error status contractual. Behavioral cases attach that caveat.

Coverage: account creation/retrieval; document 9/10/14/15-digit boundaries, empty/nondigit/missing/null/numeric and isolated duplicates; all four operations with identity/type/sign/caller-unit value; zero/negative/0.001/0.01/1.999/10.99/max/max+0.01/very-large money; every transaction field missing/null/wrong-type; fractional/unknown operations; nonexistent account; replay/changed-body/missing key and concurrent stored count; request IDs; wrong method, malformed JSON, wrong content type, absent body, {}, [], oversized body on both write endpoints.

Bodies are flat; statuses come from response.status(); typeof is used only for types. Schemas come from YAML. Undocumented money/precision/header/error mappings are labeled policy assumptions. Examples are not implementation oracles.

Fixtures isolate identities/keys and clean local mock state. Staging has no supplied DELETE: attach IDs and use agreed retention. Reserved missing-account ID MAX_SAFE_INTEGER must remain absent under approved staging policy. T1 checks all responses plus authoritative count without filtering failures or retries. Audit/balance/security observations are explicitly skipped and fail release sign-off. A mock state count is only synthetic in-memory evidence.
